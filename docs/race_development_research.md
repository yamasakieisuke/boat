# レース展開の事前予測可能性 調査（2026-08）

**目的**: 「1コースが敗れるか／敗れたら誰が来るか」を、**レース前に観測できる情報だけ**でどこまで予測できるかを定量化し、`scripts/predictor.py` に追加すべき特徴を優先順位つきで特定する。

**位置づけ**: `docs/accuracy_review_2026-08.md` の結論「足りないのは既存指標の重みではなく持っていない情報」を受けた調査。既存指標の言い換えを新発見として扱わないよう、**主要な効果はすべて「1号艇選手の実力で層別しても残るか」を確認**している。

## 1. データと検証設計

### 使用データ
`data/results_csv/*.csv` 505ファイル / 438,024行。

レース単位に再構成した結果：

| 区分 | レース数 |
|---|---|
| 全グループ | 74,153 |
| 6艇そろい | 68,964 |
| 着順が1-6の順列（欠場等を除外） | 68,716 |
| **進入コースが1-6の順列（本調査の主対象）** | **65,460** |

- `course_enter` 欠損は 20260322〜20260516 の50日。この期間は進入ベースの分析から除外した。
- `venue_name` は195日分で約半数が空欄。会場別の分析はその行のみを使う（24会場すべて出現するため会場間比較は成立するが、会場ごとのnは全体の約1/4に落ちる）。
- 同一 (date, venue, race_no) に**別レースが2件入っている**ケースが多数あり（例: 20250315 桐生R12 が「記者選抜戦」と「一般桐生特選」の2件）、枠番の重複でレースを分割して対処した。単純に (date,venue,race_no) でgroupbyすると壊れる。

### リーク対策
- 選手のコース別実績・前づけ率は、**日付順に前進しながら「その日より前の全レース」だけ**で構築した（同日のレースは互いに参照しない）。
- モデル評価は時系列分割。主要な結果は **train: 〜2026-01-31 / test: 2026-02-01〜2026-08-14 (20,009R)**。加えて 20251201 / 20260601 の2分割でも再現を確認（§4.4）。
- 縮約（shrinkage）の事前分布だけは全期間の定数6個を使っている。実質的な漏れは無視できる範囲。

### 目的変数の使い分け
- **「1コース1着」**（進入ベース）: 展開そのものの分析に使用。基準値 **55.5%**。
- **「1号艇（枠1）1着」**: predictor の本命頭に直結するため、提案・モデル評価に使用。基準値 **55.1%**（test期間 55.6%）。
- 枠1が進入1コースに入る率は 98.9% なので両者はほぼ一致する。

### 2.4 風向は効かない（明確な否定的結果）

`predictor.py:932-938` は「北・北東・北西 = 向かい風／南・南東・南西 = 追い風」という**全国一律の判定**をしている。これを検証した：

| 風向グループ | 弱風(0-2m/s) | 強風(≧4m/s) |
|---|---|---|
| 北系（現行=向かい風） | 58.9% (n=11,094) | **52.1%** (n=7,411) |
| 南系（現行=追い風） | 57.5% (n=11,078) | **52.2%** (n=7,755) |
| 東西 | 57.5% (n=5,546) | 52.4% (n=3,968) |

**強風時の1コース勝率は風向によらず 52.1〜52.4% で完全に一致**。この判定に識別力は無い。

会場ごとに向きが違うから一律判定が悪いのか？も検証した。会場×風向のダミー（風速でスケール）を追加した時系列検証：

| モデル | test AUC | logloss |
|---|---|---|
| 会場 + 風/波/天候 + race_no/種別 | 0.6186 | 0.6648 |
| ＋ **会場×風向** | **0.6154** | **0.6688** |

**out-of-sample で悪化**。会場別に見た「強風−弱風」の差は方向によってバラつくが（住之江×北西 −29.0pt など）、それは過学習であり将来に持ち越さない。

> 会場ごとの水面の向きを与えれば「対1マーク向かい風」を正しく計算できる可能性はあるが、**本データ（絶対方位のみ）からは復元できなかった**。

### 5.4 頭を1号艇から替えても的中は上がらない（重要）

「予測確率が閾値未満なら、コース別1着率が最大の2-6号艇を頭にする」戦略の1着的中（test 20,009R）：

## 6. predictor.py への追加提案

### 6.0 【P0・最優先】会場データファイルの欠落を確認する

`scripts/predictor.py:899` の `calc_venue_course_mod()` は、冒頭で

```python
if not venue:
    return base            # ← COURSE_BASE_SCORE をそのまま返す
```

としており、`venue` は `load_venue_data(jcd)` → `data/venues/venue_characteristics.json` から来る。ところが：

- `data/venues/` ディレクトリが**リポジトリに存在しない**
- `.gitignore` は `data/*` を無視し、例外指定は `results_csv` / `players` / `motors` / `logs/verify_history.json` / `fetch_requests.json` のみ。**`data/venues/` は例外に入っていない**
- `data/venues/*.json` を生成する `scripts/scrape_stadium_data.py` は、`.github/workflows/*.yml` のどこからも呼ばれていない
- `predict.yml` は checkout → pip install → `run_morning.py` のみで、会場データを取得するステップが無い

つまり **CI 上では会場・季節・潮汐・風の course_mod がすべて適用されず、`course_advantage` は「枠番だけで決まる定数」になっている可能性が高い**。accuracy_review が観測した「course_advantage の幅 0.2972 が突出」「スコアの大半が枠で決まっている」はこれで説明がつく。

**まず実行環境で `data/venues/venue_characteristics.json` の有無を確認すること。** 無ければ、以下の提案はどれも「重みの調整」ではなく「そもそも動いていなかった経路を動かす」話になる。§2.1 の会場別1コース勝率表をそのまま `venue_course_mod` の実測値として使える（全国平均 55.5% との比率）。

### 6.1 【P1】進入固定の判定を修正する（実装コスト最小・効果最大）

**現状のバグ**: `_RACE_TYPE_QUALIFIER` は `(予選|敗者復活|一般|B級|...)` にマッチする。実データの race_name には `予選 進入固定` / `一般 進入固定` が存在し、これらは **qualifier に分類され `RACE_TYPE_BONUS = 0.87`（荒れ補正）が適用される**。実測は **70.9%（+15.4pt、全体で最も堅い部類）** なので、補正が真逆。

**提案**:
```python
_RACE_TYPE_FIXED = re.compile(r"進入固定")
# 分類の最優先で判定し、finalist より強い係数を当てる
RACE_TYPE_BONUS["fixed"] = 1.20   # 実測 70.9% / 55.1% ≒ 1.29 を控えめに
```
- 入力: `data/racecards/*/*.json` の `race_name`（`"カタメン１予選\n\t\t1800m"` の形式で取得済み）
- 発火率 2.7%（芦屋・常滑・下関・若松・蒲郡・大村・丸亀に集中）
- 期待効果: 該当レースで1号艇の確信度 +15pt。1号艇本命の妥当性が正しく評価される

### 6.2 【P2】前づけ率（`maedzuke_rate`）を新規指標として追加

**もっとも「展開情報」らしく、predictor に完全に欠けている特徴。**

**計算方法**（`scripts/build_stats.py` に追加、`compute_st_stats` と同じループで取れる）:
```python
# 選手ごと: 過去レースで course_enter < waku だった割合
maedzuke_rate = sum(1 for r in rows if int(r["course_enter"]) < int(r["waku"])) / len(rows)
# players/{reg_no}.json に "hist_maedzuke_rate": {"rate": float, "races": int} として保存
```
※ `course_enter` は 20260322〜20260516 が欠損なのでその期間はスキップすること。

**predictor 側**（レース単位の補正、艇ごとの加点ではない）:
```python
# 3-6枠の選手の前づけ率の最大値（20走以上の選手のみ）
mz = max(rate(reg) for waku 3..6 if races>=20)
if   mz >= 0.25: course_mod_1 *= 0.80   # 実測 44.8% / 55.1%
elif mz >= 0.15: course_mod_1 *= 0.91   # 実測 50.3% / 55.1%
# 同時に 4-6コースの course_mod を引き上げる（勝者枠 w5/w6 が約2.5倍になるため）
```
- 発火率: 4.2%（≧25%）／9.7%（≧15%）
- 期待効果: 該当レースで −10〜16pt。**進入が実際に乱れる確率が 12.8% → 75.5% に跳ね上がる群**を事前に特定できる
- 注意: predictor は展示進入 (`get_actual_entry_course`) をすでに見ているが、(a) 展示データが取れないケースがある (b) 展示進入と本番進入は一致しない (c) 現状のペナルティは ×0.97/×0.95 と効果に対して小さすぎる（実測は ×0.80 相当）

### 6.3 【P3】風の扱いを「風向判定」から「会場別・風速の連続関数」に置き換える

**現状**: `calc_venue_course_mod()` は `wind_speed >= threshold(4)` で階段的に発火し、**全国一律の北系/南系判定**で headwind/tailwind の course_mod を切り替える。§2.4 のとおりこの判定に識別力は無い。加えて §6.0 のとおり `wind_cfg` は空で、そもそも `[1.0]*6` にフォールバックしている。

**提案**: 風向を捨て、風速の連続関数にする。
```python
# 1コースへの補正。閾値なしの連続関数
excess = max(wind_speed - 2, 0)
course_mod_1 *= (1 - VENUE_WIND_SENS[jcd] * excess)
```
`VENUE_WIND_SENS`（1m/sあたりの1コース勝率低下、§2.3 の Δ を風速差で割ったもの）:

| 感応度 | 会場 | 目安の係数 |
|---|---|---|
| 高 | 常滑・下関・芦屋・若松・浜名湖・唐津・びわこ・徳山・桐生 | 0.030 |
| 中 | 江戸川・住之江・平和島 | 0.015 |
| 低（床効果） | 津・戸田・三国・多摩川・尼崎・宮島 | 0.000 |
| 未計測（n不足） | 鳴門・大村・丸亀・蒲郡・児島・福岡 | 0.015（全国平均） |

- 期待効果: 強風時（14.9%）で 1コース確信度を平均 −5pt、感応度の高い会場では −15pt
- 副作用: 波高は風速と強く相関するため、両方入れると二重計上になる。**風速だけを使うこと**

### 6.4 【P4】相手（2-6号艇）のSTを「脅威」としてレース単位で見る

**現状**: `calc_st_score()` は各艇に独立にSTスコアを与えるだけで、艇間の比較はスコアの大小を通じてしか起きない。`course_advantage` が支配的なため、外の速いSTが1号艇の評価を下げる経路が存在しない。

**提案**: レース単位の補正項を1つ追加。
```python
# 4-6枠の選手の平均ST（既存の players/*.json の hist_avg_st.avg_st で足りる）
st_adv = avg_st(waku1) - min(avg_st(w) for w in 4,5,6)
# st_adv > 0 = 外のほうが速い
course_mod_1 *= (1 - clamp(st_adv, -0.02, 0.02) * 6)   # ±0.02秒で ±12%
```
- 効果量: 四分位間で **各層 −7.7〜13.0pt**（marginal −21.8pt のうち約半分が独立成分）
- 発火率: 100%（連続値）
- **重要**: コース別ST (`hist_avg_st.course_st`、すでに players json にある) を使う必要は**ない**。通算平均ST (`hist_avg_st.avg_st`) で同じ性能が出る（§4.4）。実装が軽い方でよい

### 6.5 【P5】race_no を course_advantage の補正に入れる

R2-R4 が 46.9%、R11-R12 が 69.2%。選手の格で層別しても各層で 8〜11pt 残る（§2.2）。predictor には `race_no_tendency` という枠があるが `venue_characteristics.json` 依存で現状は無効（§6.0）。

```python
RACE_NO_MOD = {1:1.12, 2:0.89, 3:0.89, 4:0.89, 5:1.01, 6:0.94,

```
（§2.1 の実測 / 55.5% をそのまま比にしたもの。実装時は 0.5 乗などで弱めることを推奨）

R1 が特異に高い（58.8%）のは、朝一で進入が枠なりになりやすいことが要因と思われる。

### 6.6 【P6】1コース敗戦時の相手選びを「コース別1着率」に統一

「1号艇を切る」と決めたレースで、2-6号艇のうち **コース別1着率が最大の艇**を対抗頭にすると 38.9%（常に2号艇なら 30.6%）。`data/players/*.json` の `hist_global_waku_stats.{course}.1st_pct` がそのまま使える。

## 7. 制約と注意

1. **サンプルが小さい層**: 進入固定の層別セル（n=203〜447）、前づけ率≧25%の層別セル（n=189〜240）、Q1×R12（n=98）、会場×風速の弱風/強風セル（一部 n=150〜250）。方向は一貫しているが、係数の数値は保守的に扱うこと。
2. **会場別の集計は n が全体の約1/4**。`venue_name` が195日分で半数欠損しているため。24会場すべてが出現するので比較は成立するが、鳴門・大村・丸亀・蒲郡・児島・福岡は風速別に割ると n が足りない。
3. **`course_enter` は本来レース前には観測できない**。本調査で「事前特徴」として使ったのは**過去のレースから集計した選手の傾向**のみで、当該レースの進入は使っていない。predictor は展示進入を見られるので、実運用ではもう少し有利な条件にある。
4. **オッズとの突合ができていない**。`output/wordpress/*_payload.json`（3,317R, 2026-03-15〜05-17）は `course_enter` 欠損期間と重なるため結合不能。ROI 分析は結果CSVの払戻から再構成した近似であり、任意の買い目のシミュレーションはできていない。
5. **予測性能 ≠ 収益性**。§5.5 のとおり本モデルの情報はオッズに織り込まれている。改善対象は「予想の的中率と説明の質」であって「回収率」ではない。
